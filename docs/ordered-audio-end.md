# Ordered audio completion

SamuraiBFF sends an empty `AudioChunk` on `audio.raw` with Kafka header
`x-audio-end=true` (UTF-8) after draining a normally closed audio socket. The
marker retains the audio's session key, partition, tenant, sample rate, language,
and stream-control headers. It uses the same ordered, idempotent producer as
the audio. It is not a Kafka tombstone or a separate session-status event.

The recorder closes/uploads the existing WAV and emits `recordings.finished`
immediately on consuming that marker. It accepts only an empty payload whose
Kafka key and tenant match the recording; duplicate markers and markers without
an active recording do nothing. `RECORDER_IDLE_SECONDS` remains 30 seconds by
default for abnormal disconnections and older producers. Start a new session
after completion; this adds no resumable-recording or crash-recovery protocol.

Refinement workers ignore the empty chunk and keep their existing idle-tail
behavior. Realtime gRPC receives only audio and its usual half-close. No protobuf,
database, topic, finalizer, storage-retention or tenant-access changes are needed.
Deploy the recorder before the BFF to enable immediate completion; older BFFs
remain compatible through the timeout.

`tests/test_recorder_worker_integration.py` uses real Kafka and an isolated
recorder subprocess to check exact WAV bytes, immediate marker completion,
timeout fallback, stream-control propagation, duplicate and empty markers.
Set `KAFKA_BOOTSTRAP` to an existing local broker to avoid starting a test broker.
Nanosamurai's Qwen Compose smoke checks actual Stop latency and partition order
through the BFF, recording storage, Qwen workers and persisted transcripts.

Validation on 2026-09-20 passed both recorder Kafka integration cases and 12
stream-control/shared-worker regressions. The complete real Qwen Compose smoke
passed with rebuilt BFF/recorder images: normal Stop reached recording completion
in 0.364 seconds; interrupted input used the unchanged fallback (30.794 seconds).
WAV bytes, transcript persistence, playback, duplicate/empty markers and tenant
isolation passed. This removes recorder waiting, not model inference time.

The marker is generated by the authenticated/tenant-scoped audio path, not from
client-provided Kafka headers. Kafka remains a trusted internal boundary; keep
its existing network/access restrictions. No credentials or audio are added to
logs or source control.
